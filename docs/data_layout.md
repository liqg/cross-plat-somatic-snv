# Data layout

All scripts resolve paths from three environment variables (or the equivalent
keys in `config/config.yaml`):

| Variable | Default | Meaning |
|----------|---------|---------|
| `CPSNV_DATA_ROOT` | `<repo>/data` | downloaded inputs (FASTQ, reference, GIAB, Twist truth) |
| `CPSNV_WORK_ROOT` | `$CPSNV_DATA_ROOT/work` | pipeline outputs |
| `CPSNV_RESULTS` | `<repo>/results` | tables, figures, logs, intermediates |

The directory names under `work/` follow the original analysis tree so that the
revision scripts can be reused unchanged.

## Sample IDs

`config/samples.tsv` lists every library × platform dataset.  The
`sample_id` column defines the FASTQ and BAM names:

```
{platform}_{sample}_{library}
e.g. SURFSeq_5000_HG004_GM23121213
```

FASTQ files are expected at `data/fastq/{sample_id}_R1.fq.gz` and `_R2.fq.gz`.
`config/simulations.tsv` maps each donor–background pair to its two libraries
and gives the depth grid, VAF range and random seed.

## Per-pair working directories

`data[].id` in the PosMix config is a platform name, not a pair ID.  Run each
donor–background pair in its own directory (`4.train/12`, `4.test/45`, …); the
driver does this automatically.  Sharing one directory between pairs would
overwrite outputs.

## Notes

- The panel BED, the 10 pairwise donor–background intersection BEDs
  (HG001–HG005), and the single-donor `intersect_HG001_panel.sort.bed` used for
  the Twist/HG001 simulation are shipped in `reference/panel/`.  Each has
  `.gz`/`.tbi` companions for the callers.  Intersection names sort the two
  sample IDs, so pair 21 (HG002 donor, HG001 background) uses
  `intersect_HG001_HG002_panel.sort.bed`.
- Position–frequency tables used in the paper are shipped in
  `workflow/pos_files/`.
- `prepare_giab_inputs.py` regenerates `data/posfiles/donor_vcf/` and the
  `giab_panel_vars.pkl` used by the donor-fragment audit.
